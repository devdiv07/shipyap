# Shipyap 0.2.0

The demo video (`shipyap-demo.mp4`) is attached to this release.

Three changes for people using it: it catches posts that claim more than the code shows, it can
write in your own voice, and it can run on your Claude plan instead of API credits.

## It catches code overclaims

A post about code can say more than the code does. For example, it might say a check "makes
failures visible" when the code only sets a flag, or "a value means X" when another line changes
that value.

- **Must fix: the code doesn't show that outcome** (`CODE_OUTCOME_UNSUPPORTED`). The sentence
  cites only code but states what happens at runtime. Rewrite it to say what the code does.
- **Must fix until checked: the meaning is incomplete** (`CODE_MEANING_INCOMPLETE`). The sentence
  says what a value means, but the value is also set outside the cited lines. Those other lines
  are sent to the fact check. The sentence unblocks only if the fact check sees them and says
  SUPPORTED.
- The fact check prompt (f2) now tells the model to check each of those extra lines against the
  sentence's own condition.
- `shipyap factcheck --config pros.toml --draft ID` re-runs only the fact check for a draft you
  already have. Without `--allow-paid` it shows what it would send and its cost ceiling, and sends
  nothing.
- Only one draft per repository waits for review at a time. Other repositories get a turn.
- When a run refuses a story, the run summary now says why.

## It writes in your voice

- `voice = "dry-nerdy"` in `pros.toml` gives short posts of 300 to 800 characters: what happened,
  what was wrong, what got fixed, and one dry line. There are no headers, lists or labelled
  sections.
- `author_style_file` points to a short file describing how you write. It sets tone only and is
  never a source of facts. `examples/author-style.example.md` is a starting point.
- That one dry line can't sneak in a fact. A joke line that holds a number, a quote, a file or
  function name, or a claim about the code is blocked (`FRAMING_HAS_CLAIM`), and repair first
  tries trimming it.
- Posts end with your repository link. With `built_by_me = true` on a repository, the last line
  says you built it.
- New style hints (they never block): AI-sounding words, clichés, "it's not X, it's Y", long or
  jargon-heavy openers, very long sentences and flat rhythm.
- When an X post doesn't fit 280 characters with the full scope line, it uses the shortest scope
  sentence from your repo that does. If nothing fits, there is no X post.
- When you approve a post you can rate it 1 to 5. The rating is kept with your eval cases.

## It can use your Claude plan instead of API credits

With `provider = "claude-plan"`, model calls go through Claude Code on your computer and count
against your Pro or Max plan. You need no API key or API credits. The prompts, checks, fact check,
repair and review page are the same as on the API.

- `scripts\model-plan.ps1 -Doctor -Config pros.toml` checks your setup with one tiny call.
- `plan_calls_per_day` (default 8) caps calls, and `plan_window` can limit them to certain hours.
- The timer works on this route. Run `setup.ps1` without `-EnablePaid`.
- If you are signed out or hit your plan's limit, you get one notification and it waits.
  Nothing is sent in the meantime.
- `shipyap settings --config pros.toml` prints the settings it actually reads.

See the README section "Use your Claude plan (no API credits)" for setup.

## Known gaps

- Checks are text rules, not a code parser. A claim about how two parts connect (for example "the
  page sends uploads through the server route") can pass when only a code comment says so.
- A claim like "the tests can fail a build" isn't caught when no CI configuration is in the
  snapshot.
- Style hints are rules of thumb. Real models haven't been tested much with the dry-nerdy
  prompt.
- The Claude plan route and the timer have been tested only on Windows. `provider =
  "chatgpt-plan"` is reserved and refused for now.
- Plan calls use your plan's normal usage. A run that needs a fact check and repair takes several
  calls.
- Code-only repositories still produce drafts that need correcting. The fact check can miss
  mistakes, so read every claim and its source before approving.
